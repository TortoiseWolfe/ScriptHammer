# ScriptHammer: Lights, Camera, Action — business plan (for the team meeting, Nov 7, 3 PM ET)

## The game and the contest
- Game: **ScriptHammer: Lights, Camera, Action** — kids run a concert from the
  soundboard: SOUND board, LIGHT board (sun first, effects layer), CAMERA
  board (zoom), plus kid-adjustable stage marks.
- Live now: https://scripthammer-stage-play.base44.app (Base44 app
  6aef664959da5bf44cba19a2, Jonathan's account, "Turtle's Workspace", FREE plan).
- Contest: Base44 × Nitro Web Game Contest. **Submissions close Dec 3, 2026,
  23:59 UTC. Winners announced Dec 10.** $65,000 total (1st $25,000; Community
  Favorite $15,000). Judged on Gameplay, Creativity, Technical Execution.
- Hard rules that shape the plan: game must be a NEW build created during the
  submission window (it is — built Nov 7); free to play, browser-only, no
  downloads, no logins; ONE entry per participant; after submissions close
  (Dec 3) NO material changes until winners are announced (Dec 10).

## Code ownership and the export plan
- **We own the code.** Base44's own FAQ: "You own everything you build on
  Base44: your code, your data, your users." Base44 hosts it; they don't own it.
- **Export is tier-gated.** Free: view code only. Starter: edit in place.
  Builder ($50 for one month, month-to-month): full export — ZIP download of
  the whole project, two-way GitHub sync into our own repo, CLI eject.
- **The plan: buy ONE month of Builder AFTER the contest.** Start it right
  after winners are announced (about Dec 11), export everything in the first
  days (GitHub sync + ZIP), verify the exported copy runs, cancel before it
  renews (by about Jan 9). Total cost: $50, once.
- Why not during the contest: GitHub sync is two-way and automatic — a stray
  push could change the live game during the Dec 3–10 no-changes window, and
  connecting GitHub also retires pre-connection version history. After
  Dec 10 neither risk exists.
- Why it's easy for THIS game: no accounts, no database, no logins by design —
  leaving Base44 later is re-hosting a front end, not rebuilding a backend.
  The long-run full-city version can then be developed from our own copy.
